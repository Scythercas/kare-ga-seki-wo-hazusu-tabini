# シーンYAMLの書きかた

セリフやシーンの実データは **`scenes.yaml` が原本**です。
`scenes.json` はそこから生成される中間ファイルなので、**直接編集しないでください**。

```
python build_scenes.py    # scenes.yaml → scenes.json
python validate_scenes.py # 192ルート走査・到達分布・整合チェック
```

編集したら必ずこの2つを実行してください。

---

## 1. いちばん基本

```yaml
  - id: scene_01
    見出し: 遭遇
    背景: bg_station
    BGM: bgm_daily
    本文:
      - 友人と二人、駅前の通りを歩いていた。特に予定があったわけではない。
      - 彼女: ごめんなさい、急に。買い物の帰りで、たまたま
      - 友人: お、奇遇だな。彼女だよ。
    次: scene_02
```

- **文字列をそのまま書けば地の文**になります
- **`彼女:` / `友人:`** で始めればそのキャラのセリフです
- プレイヤーに専用のセリフはありません（選択肢がプレイヤーの発言にあたる）

---

## 2. 行に付けられるもの

```yaml
      - 彼女: あ……{{friendName}}くんの……友達、だよね？
        声: voice_01
        表情: fluster
```

| キー | 意味 |
|---|---|
| `声` | ボイスID。`recordings.json` の `voiceId` と一致させる |
| `表情` | 立ち絵の差分。**話者の差分なら名前だけ**書けばよい |
| `背景` | この行から背景を変える |
| `BGM` | この行からBGMを変える。`null` で停止（無音） |
| `条件` | この行を表示する条件（後述） |

### 2人ぶんの表情をまとめて変える

```yaml
      - 友人: お、奇遇だな。彼女だよ。
        表情: { 友人: normal, 彼女: normal }
```

### 立ち絵を画面から外す

```yaml
      - 地の文: 彼女は一瞬だけ、その背中を目で追った。
        表情: { 友人: null }
```

`null` で消えます。友人が席を外す離脱シーンで使います。

### 地の文に何か付けたいとき

素の文字列には他のキーを付けられないので、**`地の文:` と明示**します。

```yaml
      - 地の文: 店を出て、3人で街をぶらぶらする。
        背景: bg_town_day
```

### `{{friendName}}`

起動時に入力された友人役の名前に置き換わります。台本中に4箇所あり、うち🎤①と🎤⑨はボイス収録対象です。

## 3. 選択肢

```yaml
    選択肢:
      id: choice_01
      効果音: se_select
      options:
        - A: 「いいね、ちょうど暇してた」
        - B: 「お邪魔じゃないか？」
          警戒度: -1
```

- `A` `B` `C` がそのまま選択肢キーになります
- **`好感度` / `警戒度`** に増減を書きます。書かなければ変化なし
- クランプはしません（マイナスも有効。設計書 4.3）

効果値の一覧は **台本.md の「選択肢一覧」** と **設計書.md 5.1節** にあります。
**数値を変えたら `validate_scenes.py` を実行して到達分布を必ず確認してください。**

---

## 4. 選択の後に出す行

選んだ結果によって変わる行は **`選択後:`** に書きます。

```yaml
    選択後:
      - 彼女: ……ありがとう。{{friendName}}、ああいうところ、ちょっと抜けてるんだよね
        声: voice_02
        表情: smug
        条件: choice_03 == A
      - 地の文: その「ありがとう」は、水のことだけを指しているようには聞こえなかった。
        条件: choice_03 == A
```

`本文:` は選択肢の**前**、`選択後:` は選択肢の**後**に流れます。

---

## 5. 条件の書きかた

```yaml
        条件: choice_03 == A                  # その選択肢でAを選んだとき
        条件: warning >= WARNING_THRESHOLD    # 警戒度がしきい値以上のとき
        条件: affection < AFFECTION_LOW
```

- 選択肢の条件は `choice_XX == A` の形だけです
- 変数は `affection`（好感度）/ `warning`（警戒度）。`好感度` `警戒度` とも書けます
- 右辺に **定数名**（`WARNING_THRESHOLD` など）を書くと、`js/config.js` の値が使われます
  → **しきい値をコードとYAMLの2箇所に書かないための仕組み**です。数値を直書きしないでください

**条件はボイス専用ではありません。** ボイスのない地の文にも付きます。現在7箇所あり、うち3つは地の文です（設計書 4.1）。

---

## 6. 次のシーンへ

```yaml
    次: scene_02
```

条件で分岐する場合は上から順に評価され、**条件のないものが最後の受け皿**になります。

```yaml
    次:
      - 条件: warning >= WARNING_THRESHOLD
        行き先: ending_bare
      - 条件: affection < AFFECTION_LOW
        行き先: ending_none
      - 条件: affection < AFFECTION_HIGH
        行き先: ending_reject
      - 行き先: ending_success
```

これが scene_08 に書かれている**エンディング判定そのもの**です。
判定ロジックはコード側に一切書かれていないので、**ここを直せばエンドの振り分けが変わります**。
Scene8のボイス（🎤⑤/⑥）も同じ `WARNING_THRESHOLD` を見ているため、「友人が疑うセリフを言ったのにバレない」という矛盾が構造的に起きません（設計書 5.4）。

## 7. エンディング

```yaml
  - id: ending_bare
    見出し: ①バレエンド
    エンディング: true
    背景: bg_town_evening
    BGM: null          # 無音にする
    本文:
      - その場は笑って誤魔化した。
```

`エンディング: true` を付け、`次:` は書きません。最後の行まで進むと「もう一度遊ぶ」が出ます。

---

## 8. よくある間違い

| 症状 | 原因 |
|---|---|
| `話者が見つかりません` | `彼女:` `友人:` `地の文:` のどれも無い。地の文に他のキーを付けるときは `地の文:` が必要 |
| `条件を解釈できません` | `条件: choice_03 == A` のように**半角スペース区切り**で書く |
| `未知のキーがあります` | キー名の打ち間違い。使えるのは 声／表情／背景／BGM／条件 |
| 行の頭が `-` や `:` で始まる文 | YAMLの記号と衝突します。`"..."` で囲んでください |
| 到達分布が変わった | 効果値かしきい値を変えた。`validate_scenes.py` の期待値も更新が必要です |
